# Architecture Overview

- **Core Engine**: Modular TypeScript (compiled to ES Modules) in `js/`. No framework, no bundler. TypeScript source (`.ts`) and compiled output (`.js`) are both committed — GitHub Pages serves the `.js` files directly.
- **CI/CD Pipeline**:
  - **Verification**: GitHub Actions (`.github/workflows/ci.yml`) runs Build, Jest unit tests, and Playwright E2E tests (Chromium, WebKit, Firefox) on every pull request and push to master.
  - **Dependency Updates**: Dependabot (`.github/dependabot.yml`) automatically checks for outdated npm packages and GitHub Actions daily, grouping updates to minimize PR noise.
- **Data Pipeline**:
  - Trigger: GitHub Actions (`push` to master, monthly cron, or manual dispatch).
  - Fetcher: Apify `harvestapi~linkedin-profile-scraper` → `data/linkedin.json`.
  - Intelligence: Google Gemini Flash via the `gemini-flash-latest` SDK alias (always resolves to the current newest Flash model — no discovery call needed).
  - Quality gate: `looksLikeRawDump()` + `bulletsAreGood()` reject bad AI output; curated `FALLBACK_EXPERIENCES` and `FALLBACK_SUMMARY` are used when AI fails. The site never publishes raw LinkedIn text.
  - Output: `profile-data.js` — single source of truth, committed back to the repo.
- **UI System**: Vanilla CSS with theme-driven CSS variables (`.light-mode` class on `body`).
- **Verification**: Jest unit tests in `tests/resume.spec.js` (56 tests across 6 suites) + Playwright E2E tests.

## TypeScript

All `js/**` modules are TypeScript. Shared interfaces live in `js/modules/types.ts`.

```bash
npm run build       # compile .ts → .js in-place
npm run typecheck   # type-check without emitting files
```

`tsconfig.json` settings:
- `"target": "ES2020"`, `"module": "ESNext"`, `"moduleResolution": "bundler"` — preserves `.js` import extensions required for browser native ES modules.
- `"rootDir": "js"`, `"outDir": "js"` — in-place compilation so HTML doesn't change.
- `"strict": true` — full strictness including `exactOptionalPropertyTypes`.

`profile-data.d.ts` provides type declarations for the auto-generated `profile-data.js` file.

## Implementation Details

- **Module Orchestration**: `js/main.ts` bootstraps the application and wires all event listeners. `renderPage()` is the central render function — synchronous, no async work on load.
- **Rendering**: `js/modules/renderer.ts` contains pure HTML string builders for experience, skills, education, and certifications. Each function takes data + an identity `Translate` callback and returns an HTML string.
- **AI Integration**: `scripts/update-resume.js` uses `@google/generative-ai` with the `gemini-flash-latest` model alias. The `GEMINI_MODEL` constant centralises the model name.
- **State Management**: `js/modules/state.ts` — tracks active animation frames, timeouts, and UI state. `AppState` interface defines the full shape.
- **Print Optimization**: `js/modules/print.ts` generates an ATS-friendly single-page layout with a heuristic quality score (0–100). Overflow handled by `printConfig.strategySteps` — each step reduces bullets and truncates text until content fits one page.

## Key Files

| File | Role |
|------|------|
| `profile-data.js` | All resume content — auto-generated by pipeline; edit manually only when re-running locally |
| `profile-data.d.ts` | TypeScript declaration for the auto-generated `profile-data.js` |
| `js/modules/types.ts` | All shared TypeScript interfaces: `ProfileData`, `Experience`, `AtsReport`, etc. |
| `scripts/update-resume.js` | Pipeline script: reads `data/linkedin.json`, calls Gemini, writes `profile-data.js` and `health.json` |
| `js/modules/dom.ts` | All DOM element references — must stay in sync with `index.html` IDs |
| `js/modules/config.ts` | UI text constants and print strategy steps (`strategySteps`) |
| `js/modules/renderer.ts` | Pure HTML builders for each resume section |
| `assets/style.css` | All site styles: theme CSS variables, layout, animations, print rules |
| `assets/profile-photo.jpg` | Profile photo — loaded by `ui.ts` for Braille ASCII art generation and shown directly |
| `health.json` | Pipeline run status: `{ status, timestamp, gemini, apify }` |
| `data/linkedin.json` | Cleaned LinkedIn export — `moreProfiles`, `receivedRecommendations`, and photo fields are stripped on every pipeline run |

## Testing

It is mandatory to run all tests before committing changes, especially the E2E suite which verifies the 2026-ready UI features (Terminal, AI Feed, Security). Playwright tests must be executed against all three browser profiles: **Chromium**, **WebKit**, and **Firefox**.

```bash
# First time only: Install Playwright browsers (all profiles)
npm run test:e2e:install

# Run all tests (Unit + E2E on all 3 browsers)
npm run test:all

# Run individual suites
npm test              # Jest unit tests (56 tests, 6 suites)
npm run test:e2e      # Playwright E2E — Chromium, WebKit, Firefox
```

Unit test suites: profile data structure, content quality, skills integrity, health endpoint schema, source file integrity, and TypeScript setup.
E2E test suites: Site layout, Terminal & AI Feed commands/typing, Security (right-click toggle), and Responsive design.

## Important Constraints

- The `GEMINI_API_KEY` must have **no HTTP referrer restrictions** in Google Cloud Console — the pipeline runs server-side (GitHub Actions) and cannot send a browser referrer.
- `profile-data.js` uses `export const profileData = ...` ES module syntax. The pipeline reads it with `fs.readFileSync` + regex extraction, not `import`, so the format must stay on one regex-matchable line.
- The workflow commit step uses `--amend` + `--force-push` when the last commit is already `chore: sync profile data`. This keeps history flat — cron runs amend rather than stack new commits.
- Import paths in `.ts` files use `.js` extensions (e.g. `import { dom } from './modules/dom.js'`). This is required because TypeScript with `"moduleResolution": "bundler"` emits the path as-is, and the browser needs `.js` to resolve native ES modules.
